# AD2CAN Sensor Node — High-voltage motorsports Team

Firmware for the sensor-acquisition node on the FAU Formula Student car. It reads
the analog and wheel-speed sensors, publishes them on the CAN bus at 100 Hz, and
reacts to brake-light and heartbeat commands from the vehicle CAN master.

- **MCU:** STM32G473CE (Cortex-M4F, LQFP48)
- **RTOS:** FreeRTOS via CMSIS-RTOS v2
- **Clock:** 64 MHz SYSCLK (16 MHz HSE, PLL M=1 N=8 R=2)
- **Bus:** FDCAN1 in classic CAN mode, 1 Mbit/s
- **Toolchain:** STM32CubeIDE (arm-none-eabi-gcc); host tests build with GCC

## What it does

1. Samples 6 ADC channels continuously over DMA (5 used: 2 brake pressures,
   steering angle, 2 throttle position sensors).
2. Measures two wheel speeds with timer input capture.
3. Converts raw ADC counts to engineering units and packs them into three CAN
   frames sent every 10–100 ms.
4. Receives a brake-light command and a heartbeat from the CAN master, and drives
   the brake-light output and the green status LED accordingly.

## Build and flash (STM32CubeIDE)

1. **File → Open Projects from File System** and select this folder.
2. Build with **Project → Build** (Ctrl+B). Output is `Debug/High_VoltageTeam.elf`.
3. Connect an ST-Link to the SWD header (PA13 SWDIO, PA14 SWCLK) and **Run** to
   flash and start the target.

If the build cannot find `app_init.h` or other `App/` headers, add the include
paths under **Project → Properties → C/C++ General → Paths and Symbols → Includes
(GNU C)**, for all configurations:

```
App/Inc
App/Inc/HAL
App/Inc/Tasks
App/Inc/Drivers
```

and make sure `App/Src` (and its `HAL`, `Tasks`, `Drivers` subfolders) are listed
under the **Source Location** tab.

## Architecture

Initialization runs in `main()` (peripherals) and then `App_Init()` /
`App_Start()` in `app_init.c` (RTOS objects, then ADC/CAN start). After
`osKernelStart()` the system is interrupt- and task-driven:

| Task            | Priority     | Period / trigger        | Role |
|-----------------|--------------|-------------------------|------|
| SensorTask      | Normal       | ADC queue (blocking)    | Convert raw ADC to engineering units into the shared struct (mutex-protected) |
| CanTxTask       | Normal       | 10 ms                   | Pack and transmit 0x510/0x511 (100 Hz) and 0x512 (10 Hz) |
| CanRxTask       | BelowNormal  | 1 s                     | Toggle green LED as a local heartbeat unless the master is sending heartbeats |
| BrakeLightTask  | Normal       | brake queue (blocking)  | Drive PA8 from the received brake command |
| defaultTask     | Normal       | 1 ms                    | CubeMX idle task |

Interrupts feed the tasks through queues:

- **ADC DMA complete** → posts the 6-channel buffer to the ADC queue.
- **TIM3 / TIM15 input capture** → records wheel-speed pulse periods for RPM.
- **FDCAN1 RX FIFO0** → routes 0x200 to the brake queue and applies 0x100
  (heartbeat) to the green LED.

All peripheral IRQs run at NVIC priority 6, below the FreeRTOS syscall threshold
(5), so they may call the `...FromISR` API safely.

## CAN message map

Standard 11-bit IDs, classic CAN, little-endian payloads.

### Transmitted

| ID    | Period | Len | Payload |
|-------|--------|-----|---------|
| 0x510 | 10 ms  | 8   | APPS1 (u16), APPS2 (u16), steering 0.1° (i16), brake front (u16) |
| 0x511 | 10 ms  | 7   | RPM left (u16), RPM right (u16), brake rear (u16), WS status (u8: bit0=L, bit1=R) |
| 0x512 | 100 ms | 4   | brake rear (u16), brake front (u16) |
| 0x700 | once   | 1   | startup magic 0xAA |

### Received (hardware filter accepts only these)

| ID    | Len | Payload |
|-------|-----|---------|
| 0x200 | 1   | brake-light command: 1 = on, 0 = off |
| 0x100 | 1   | heartbeat: green LED state, 1 = on, 0 = off |

CAN IDs and the startup ID are defined in `App/Inc/app_config.h`.

## Sensor conversions

Calibration constants live in `App/Inc/app_config.h`; the math is in
`App/Src/Drivers/sensors.c`.

- **Brake pressure:** linear from ADC counts 400–3610 to 0–20000 (0.0–20.0 bar).
  Out-of-range readings return 0.
- **Steering angle:** linear from ADC 1736 (full left) to 3561 (full right),
  output −900…+900 (−90.0°…+90.0°).
- **RPM:** from the input-capture period, `RPM = 64e6 * 60 / (period * 25)` for a
  25-tooth wheel; reported as 0 after 500 ms with no pulse; smoothed by a
  10-sample moving maximum.

## Key configuration values

| Setting | Value | Where |
|---------|-------|-------|
| CAN TX period | 10 ms (100 Hz) | `app_config.h` `CAN_TX_PERIOD_MS` |
| ADC channels | 6 (scan, DMA, 12-bit) | `app_config.h` |
| Wheel-speed filter | 10 samples | `app_config.h` `WS_FILTER_SIZE` |
| FreeRTOS heap | 32 KB | `Core/Inc/FreeRTOSConfig.h` |
| Tick rate | 1000 Hz, timebase TIM6 | `Core/Inc/FreeRTOSConfig.h` |
| FDCAN bit timing | prescaler 4, 1+12+3 TQ, 81.25% sample | `.ioc` / `MX_FDCAN1_Init` |

## Tests

Host-side tests (Unity framework with mocked HAL, CMSIS-RTOS and FreeRTOS) cover
the sensor math and task logic without hardware. They live in `Tests/`:

```
Tests/Unit/          Per-module unit tests (HAL wrappers, tasks, sensors)
Tests/Integration/   Cross-module behaviour
Tests/Acceptance/    End-to-end requirements
Tests/Mocks/         Fake HAL / RTOS so the code compiles on a PC
Tests/Unity/         Test framework
```

Run them from a shell with GCC on PATH (MinGW-w64 on Windows):

```
cd Tests
run_tests.bat          # Windows
```

or build with CMake (`Tests/CMakeLists.txt`). Latest recorded results are in
`Tests/TEST_RESULTS.md`. Re-run after any change to `App/`.

For on-hardware bring-up you need an ST-Link, a CAN transceiver (e.g.
SN65HVD230), a CAN analyzer, a 120 Ω bus termination, and the five analog and two
wheel-speed sensors wired to the pins above.

- After changes, run the tests (`cd Tests && run_tests.bat`) — they must be all green.

  update this README in the same commit so it always matches the code.

## Known issue

The green LED is written from two places: the CAN RX interrupt sets it directly
from a heartbeat frame (`App/Src/HAL/can_hal.c`), while `CanRxTask` toggles it
once per second when no heartbeat is active (`App/Src/Tasks/can_rx_task.c`). When
heartbeats arrive intermittently the two can fight over the pin and the LED can
flicker. Functionally the node works; the LED ownership still needs to be cleaned
up so a single owner drives it. This is the open item on the `fix-heartbeat`
branch.
